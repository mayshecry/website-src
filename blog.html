i turned a raspberry pi 3 into a wardriving machine oct 2026 // project: github.com/mayshecry/wardriving

so i turned a raspberry pi 3 into a whole wardriving machine. it's called loner_. the pi spins up a WPA-protected hotspot, you hook your phone up to it, and boom, you get a little dashboard showing every wifi network and bluetooth device floating around you. pocket-sized wireless survey console. no internet, no cdn, everything served straight off the pi. clean as hell.

the setup is two wifi radios. the pi's built-in wlan0 runs the hotspot while a usb adapter on wlan1 does the passive scans. tap a network on the dashboard and it re-scans that AP's channel and dumps all the beacon gossip: auth suites, ciphers, phy generation, vendor OUIs, management-frame protection, the works. bluetooth discovery runs through bluez, no pairing needed. everything gets logged to csv, with coordinates from gpsd or an iphone shortcut if you're feeling fancy.

and before anyone gets any ideas: it's a survey tool, not an attack tool. doesn't join networks, doesn't deauth anyone, doesn't sniff client traffic. just passive observation, fr. my redteam days are behind me. i just like knowing what's in the air around me.

obviously it's written in C. gcc, make, iw, nmcli, bluetoothctl. C is my beloved and i'm not apologizing for it. the whole thing is one small binary plus a dashboard html file chilling next to it. that part felt right.

but ngl? it was a pain in the ass to make. networkmanager beefing with me over which interface it owns. usb wifi drivers being usb wifi drivers. bluez handing me cached device names whenever it felt like it. access points switching channels or straight up vanishing mid-inspection. every layer of the stack had its own opinion and none of them agreed with each other. fix one thing, two more break. that was my life for days. i was cooked.

still. it works now. you plug it in, it prints a url, you open it on your phone and watch the airwaves. lowkey satisfying as hell. source is on github if you wanna suffer too. you'll need a pi 3, a second wifi adapter, and patience. lots of patience.

i wrote a dll injector and then its worst enemy aug 2026 // code: dll-injector + anti-dll

some weeks you just feel like poking processes. i wrote a tiny dependency-free dll injector in C that works on x64 windows AND x64 linux. one static lib, one clean C api, drop it into anything. windows side is the classic combo: CreateRemoteThread plus LoadLibrary in the target. linux side is spicier: ptrace attach, hunt down dlopen in the target's libc, carve out an RWX workspace through a raw mmap syscall, and run little trampolines that call dlopen for you. textbook redteam shit, and yes, i had fun.

but then the other half of my brain woke up and went "ok but how do you catch that." so right after, i built anti-dll: a self-contained windows library that sniffs out injected DLLs inside its own process. it cross-checks the toolhelp snapshot against the PEB loader list to find hidden modules, builds the full import graph to see what was never supposed to be loaded, scans function prologues for hook trampolines, and scores everything into CLEAN / SUSPICIOUS / INJECTED. injector vs detector. i played both sides and honestly both won.

both repos ship with test harnesses and examples so you can watch the whole thing happen end to end. redteam muscle memory paying rent in 2026.

i made my own programming language because the others were too slow jun 2026 // code: github.com/mayshecry/sharkscript-standalone

at some point every perf-obsessed dev looks at existing languages and goes "nah, i could do this faster." so i did. sharkscript is a high-performance little language with a custom bytecode VM, built for real-time packet analysis and low-latency automation where microseconds actually matter. .shark source compiles down to bytecode, and the VM runs it through an O(1) jump table dispatcher instead of some slow switch-case nonsense.

and when the VM still isn't fast enough, there's AOT mode: it transpiles your script to native Go and compiles that into a stripped standalone binary. no VM layer at all. zero overhead. plus lock-free multi-core parallelism, zero-alloc string and math engines, sync.Pool buffers, the whole nine yards. i was unwell when i wrote this. (affectionate.)

best part? ligmashark uses sharkscript as its plugin language. my network analyzer runs plugins written in my own language. the ecosystem is just me. it's beautiful. docs live at larping.today, don't ask. repo's here if you wanna see what "extreme focus on speed" looks like when i do it.

i got doom running on sharkos jun 2026 // code: src/doom

everyone writing an OS hits this phase eventually. you wake up one day and choose violence: port doom to your own kernel. so now there's a whole src/doom directory in sharkos. doom.c plus a full software renderer split into modules. bsp traversal, wall columns, floor and ceiling planes, lighting, sprites, wad gamedata loading, the entire circus. yes, my operating system runs doom. that's the whole point of an operating system, fr.

the renderer is all C, obviously. fixed-point trig tables, clip segments, visplanes, all that 1993 black magic, running on bare metal i wrote myself. no SDL, no OS underneath holding my hand. sharkos IS the OS underneath. the system layer talks straight to my own framebuffer and input. it's doom all the way down.

and yeah, it was a shit ton of work. every module fought me. bsp traversal off by one and the whole level renders inside out. columns misaligned and walls look like glitch art. planes... don't even get me started on visplanes. i'd fix the lighting and break the sprites. fix the sprites and the floors would start vomiting pixels. it kept breaking in new and creative ways every single day.

worst part? debugging a renderer on your own OS. no renderdoc, no comfy tooling, just you, a framebuffer, and vibes. half the bugs were the renderer, half were secretly my own OS lying to me underneath. that was a special kind of pain in my ass.

but then one day it just... rendered. walls, floor, ceiling, a demon staring back at me, all on sharkos. i've never felt so powerful. code's in src/doom if you wanna stare into the abyss. it runs doom. that's all i ever wanted to say.

i got tired of guessing what my pc does at 3am may 2026 // code: github.com/mayshecry/ligmashark

wireshark shows you raw packet vomit. nethogs shows you bandwidth but won't name the culprit. and there i was at 3am watching my machine talk to god knows who. so i built ligmashark: a terminal-based network analyzer that tells you exactly which process is using your network. 55 commits, 4 stars, my most starred repo. the people were also awake at 3am, apparently.

it's written in Go, lives in your terminal, and does what the other tools won't: per-process network attribution. no bloat, no telemetry, no 400-tab GUI. plus a full plugin system powered by sharkscript, my own language, with docs for features, internals, plugins, usage. i documented it like a real project and everything. growth.

if you've ever stared at a network graph wondering "who the hell is uploading right now," this one's for you. repo's here. go catch your own processes lacking.
